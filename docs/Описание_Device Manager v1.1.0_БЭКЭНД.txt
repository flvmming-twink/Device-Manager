Device Manager 1.1.0 — описание бэкенда

Архитектура
Общая серверная часть не добавлялась: SQLite остаётся единственным хранилищем каждого телефона. Передача выполняется между двумя экземплярами Android-приложения по Bluetooth Classic RFCOMM (SPP). Используется системное сопряжение Android и защищённые клиентский/серверный RFCOMM-сокеты. Android документирует этот парный вариант как аутентифицированное соединение с шифрованием канала: https://developer.android.com/reference/android/bluetooth/BluetoothDevice#createRfcommSocketToServiceRecord(java.util.UUID).

Операция работает внутри BluetoothTransferActivity. Передача, сканирование и серверный сокет закрываются при отмене, Back или завершении активности. Foreground service, фоновые задания и периодическая синхронизация отсутствуют.

Разрешения
AndroidManifest объявляет BLUETOOTH, BLUETOOTH_ADMIN и ACCESS_FINE_LOCATION с ограничением до API 30. На API 31+ объявляются BLUETOOTH_SCAN с флагом neverForLocation, BLUETOOTH_CONNECT и BLUETOOTH_ADVERTISE. Приложение не запрашивает их при старте или обновлении:
- отправка на Android 12+ просит SCAN и CONNECT;
- приём на Android 12+ просит ADVERTISE и CONNECT;
- поиск на Android 11 и ниже просит ACCESS_FINE_LOCATION;
- разрешения старых версий Android для Bluetooth нормальные, пользователь может включить сам Bluetooth через системный экран;
- если Bluetooth выключен, используется ACTION_REQUEST_ENABLE; при приёме ACTION_REQUEST_DISCOVERABLE просит временно показать телефон (180 секунд).

Формат передачи
DeviceTransferCodec формирует UTF-8 JSON envelope `{ type: "dm.devices", v: 1, count, sha256, records }`. Каждый record — снимок полей карточки в форме, совместимой с DeviceQrCodec. В кадр не входят локальный SQLite ID, даты создания/изменения и команды удаления. Статус, причина списания, место, ответственный и примечания сохраняются.

Поток RFCOMM начинается 4-байтовой длиной кадра в сетевом порядке байтов, затем идут ровно заданные байты JSON. SHA-256 от канонического массива records проверяется принимающей стороной. Кадр ограничен 8 MiB, партия — 1–250 записей. Получатель отправляет короткий JSON-ответ через writeUTF с результатом и числами добавленных и пропущенных карточек.

Импорт
До подтверждения Activity получает текущий набор инвентаря и считает совпадения по нормализованным organization + inventory number. Предпросмотр ничего не записывает. После явного подтверждения DeviceRepository.importNew вставляет все новые записи в одной SQLite-транзакции с новыми локальными ID и временными метками. Уникальный индекс базы защищает от гонки и от совпадений с корзиной: INSERT OR IGNORE оставляет исходную строку без изменений, включая удалённую. Повторное вхождение в самом пакете также учитывается как дубликат. Переданный статус действующее/на списание и остальные переносимые поля сохраняются. При отклонении или разрыве соединения записи не импортируются.

Совместимость
Приложение поддерживает API 21+, Android 5.0+. В 1.1.0 добавлена версия кода 4 и имя версии 1.1.0; target SDK остаётся 34. QR-протокол и ключи организации не изменялись и работают отдельно от Bluetooth.

Ограничения версии
- Оба телефона должны иметь приложение Device Manager с одинаковым Bluetooth-протоколом v1 и быть рядом.
- Классический Bluetooth нужен на обоих устройствах; пользователь подтверждает сопряжение системным способом.
- Приёмник принимает одну отправку в текущем foreground-сеансе и одну передачу за раз.
- Данные не удаляются и не перезаписываются на принимающей стороне; конфликтующие инвентарные номера пропускаются.
- Нет очереди в фоне, синхронизации или общего серверного каталога.
