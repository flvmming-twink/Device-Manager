Device Manager 1.1.2 — описание бэкенда

Архитектура и миграция
Серверной части нет; SQLite остаётся локальным хранилищем устройства. Версия схемы БД повышена с 1 до 2. Миграция пересоздаёт таблицу devices с разрешёнными статусами ACTIVE, NEEDS_REPAIR, BROKEN и WRITE_OFF, копирует прежние строки с теми же ID и ограничениями уникальности, создаёт таблицы истории и сверок. Данные устройств и корзины сохраняются. Для существующих карточек добавляется базовое событие начала истории; прошлые перемещения восстановить нельзя.

Статусы
DeviceStatus содержит ACTIVE, NEEDS_REPAIR, BROKEN, WRITE_OFF. Причина списания обязательна только для WRITE_OFF и очищается при возврате в другое состояние. Статусы сохраняются в QR и JSON-переносе. Старые метки ACTIVE/WRITE_OFF читаются без изменений; версия 1.1.1 не знает двух новых значений и не может корректно импортировать такие QR/JSON-записи.

История устройства
Таблица device_history хранит локальные события с ID карточки, снимком её инвентарного номера и названия, типом события, именем поля, старым и новым значениями и временем. Фиксируются создание, импорт, изменения полей, смена местоположения, смена состояния, попадание в корзину, восстановление, окончательное удаление и находка при аудите. Автор действия не записывается, поскольку в приложении пока нет учётных записей.

Массовые изменения
DeviceRepository.updateMany применяет изменения к выбранным непомещённым в корзину записям в одной SQLite-транзакции. Допускается до 500 устройств. Можно изменить location (organization/building/room), responsible и status. Для WRITE_OFF передаётся причина. Уникальный индекс организации и нормализованного инвентарного номера сохраняется; конфликт откатывает всю транзакцию. Для каждого изменённого устройства события истории создаются в той же транзакции.

Инвентаризационные сессии
Таблица room_audits фиксирует организацию, корпус, комнату, время начала и завершения. room_audit_items хранит снимок ожидаемого списка на момент старта и QR-находки, которых в этом списке не было. Сканер передаёт содержимое в DeviceQrCodec; зашифрованные метки расшифровываются через импортированный ключ организации. Идентичность сверяется по нормализованным organization + inventory number.

Повторное сканирование одной метки в сессии не дублирует результат. Итог считает ожидаемые, найденные, отсутствующие и лишние карточки. Завершение аудита не меняет device.location, status или deleted_at: пользователь сверяет результат и при необходимости выполняет отдельное массовое изменение. Для известных карточек факт находки добавляется в device_history.

Совместимость и ограничения
- applicationId ru.misis.devicemanager, versionCode 6, versionName 1.1.2; Android API 21+, target SDK 34.
- История и сессии остаются на текущем устройстве и не синхронизируются с другими телефонами.
- Новые состояния требуют Device Manager 1.1.2 или новее при обмене QR/JSON.
- Для аудита камера запрашивается только при нажатии «Сканировать устройство». Защищённый QR требует соответствующий приватный ключ организации.
