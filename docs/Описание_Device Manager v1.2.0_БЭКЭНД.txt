Device Manager 1.2.0 — описание бэкенда

Архитектура
Приложение использует локальную SQLite-базу как рабочее хранилище и Cloud Firestore как общую базу синхронизации. Отдельный физический сервер и пользовательский аккаунт не нужны. Для передачи данных между сетями организация создаёт Firebase проект Google и собирает APK с его конфигурацией.

SQLite и миграция
Схема локальной базы повышена до версии 3. Таблица `devices` получает nullable-поле `cloud_id`; очередь `cloud_sync_queue` хранит облачный документ, действие UPSERT/DELETE, предыдущий идентификатор и время изменения. Миграция с версии 2 добавляет поле и индекс, не удаляя карточки. Миграция версии 1 сначала выполняет прежний переход на схему истории v2, затем добавляет облачные поля.

Идентичность карточки
Облачный ID — SHA-256 от нормализованных названия организации, нулевого разделителя и инвентарного номера. В идентификатор не входят локальный SQLite ID и кабинет, поэтому один объект остаётся тем же документом при перемещении. При изменении организации или инвентарного номера новая карточка содержит ссылку на предыдущий облачный ID; старая запись удаляется из общей коллекции.

Создание и подключение
Каждая установка создаёт анонимного Firebase Authentication пользователя. Создание общей базы формирует случайный 16-символьный Base32-код (80 бит энтропии), создает документ организации, членство владельца и отдельный документ для каждой карточки. Подключение по коду добавляет членство участника, загружает карточки Firestore, объединяет их с локальным SQLite по облачному ID или нормализованной паре организация/инвентарный номер, затем помещает локальные записи в очередь отправки.

Синхронизация
`CloudSyncManager` регистрирует Firestore snapshot listener для коллекции устройств, применяет добавленные и изменённые записи к SQLite, обрабатывает удаления, сообщает о сетевом статусе и отправляет накопленную очередь пакетами до 100 операций. Запись пользователя сохраняется локально, сразу попадает в outbox и отправляется при доступной сети. `ConnectivityManager` запускает повторное подключение и отправку при восстановлении сети; очередь сохраняется при завершении процесса приложения. Если локальная операция ждёт отправки, более старый входящий снимок не перезаписывает её.

Конфликт и область синхронизации
Если несколько телефонов редактируют одну карточку без сети, последняя успешно отправленная полная карточка заменяет предыдущую; автоматического объединения полей или журнала конфликта нет. Карточки в корзине синхронизируются как записи с deletedAt; окончательное удаление убирает документ из Firestore и локальную карточку. События истории, результаты комнатного аудита, настройки отображения и QR-ключи не синхронизируются.

Доступ и правила Firestore
Код общей базы — bearer-приглашение: пользователь, знающий код, может добавить себя в список участников и читать/изменять реестр. Запрос списка общих баз запрещён правилами; права на дочерние документы проверяются по членству. Rules находятся в `firebase/firestore.rules` и должны быть опубликованы в консоли Firebase. В правилах ограничены поля и допустимые статусы устройства. При утрате или публичном раскрытии кода следует создать новую общую базу и сообщить новый код разрешённым пользователям.

Настройка сборки
Gradle применяет Google Services plugin только если файл `app/google-services.json` существует. Файл добавлен в `.gitignore` и не публикуется вместе с открытым исходным кодом. Без него `FirebaseApp` не инициализируется, экран общей базы сообщает о необходимости настройки, остальная функциональность остаётся локальной. Настройка Auth, Firestore, регион, правила и ограничения тарифа описаны в `firebase/SETUP.md`.

Зависимости и совместимость
- Firebase Android BoM 35.2.0, Firebase Auth и Cloud Firestore.
- Android Gradle Plugin 9.1.1, Kotlin Gradle Plugin 2.4.21, Gradle 9.3.1, JDK 17. AGP 9 uses compatibility switches for the existing Kotlin plugin and Android DSL while preserving the Kotlin 2.4 metadata support required by this build.
- minSdk 24 (Android 7.0), targetSdk 34.
- Добавлены INTERNET и ACCESS_NETWORK_STATE; пользовательское разрешение во время выполнения не запрашивается.
- `versionCode` 8, `versionName` 1.2.0.
