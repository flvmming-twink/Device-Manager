# Device Manager QR, версия протокола 1

Версия приложения: 1.0.1. QR содержит JSON в UTF-8, а не URL сервера. Работа полностью автономная. Старые контактные QR не импортируются как устройства.

## Открытый режим

Объект `{"type":"dm.device","v":1,"device":{...}}`. Поля устройства: `name`, `inventory`, `serial`, `category`, `organization`, `building`, `room`, `responsible`, `status` (`ACTIVE`, `NEEDS_REPAIR`, `BROKEN` или `WRITE_OFF`), `reason`, `notes`. Передаются все поля, включая заметки и ответственного. Локальные ID, даты SQLite и команды удаления не передаются. Открытый JSON доступен любому сканеру; это не шифрование. Статусы `NEEDS_REPAIR` и `BROKEN` появились в Device Manager 1.1.2; более ранние версии их не распознают.

## Защищённый режим

Гибридная схема: открытый JSON шифруется случайным AES-256-GCM, а ключ AES — открытым ключом RSA-2048-OAEP. OAEP использует SHA-256 и MGF1-SHA-256, явно заданные через OAEPParameterSpec. Новые ключ AES и 12-байтный nonce создаются для каждой метки. GCM tag — 128 бит. Шифротекст содержит tag в конце.

Внешний JSON: `type=dm.device.enc`, `v=1`, `alg=A256GCM+RSA-OAEP-256`, `kid`, `ek`, `iv`, `ct`. Бинарные поля закодированы обычным Base64 без переносов. `kid` — первые 16 байт SHA-256 от DER SubjectPublicKeyInfo открытого ключа, 32 lowercase hex-символа. AAD в UTF-8: `dm.device.enc|1|A256GCM+RSA-OAEP-256|<kid>`.

`ek` — RSA-шифротекст ключа AES (256 байт), `iv` — nonce, `ct` — AES-шифротекст с tag. Изменение данных или связанного заголовка приводит к ошибке. Это конфиденциальность и целостность шифротекста, не цифровая подпись сотрудника и не подтверждение актуальности карточки. Владельцы общего ключа имеют одинаковый доступ; ролей и отзыва доступа в этой локальной версии нет.

## Ключи организации

В APK нет общей пары RSA или секретного пароля. Пользователь создаёт одну или несколько пар, выбирает активную для новых меток и сохраняет файл для коллег/резервной копии. Старые импортированные ключи сохраняются для чтения ранее созданных меток.

На телефоне ключи находятся в приватном внутреннем каталоге приложения `files/qr-keys`; Android backup отключён. Файлы внутри песочницы не защищены дополнительным аппаратным хранилищем: доступ к скомпрометированному устройству выходит за гарантии этой версии. Удаление приложения удаляет локальные ключи.

Экспорт ключа всегда шифруется AES-256-GCM с новым nonce и солью 16 байт. Ключ файла выводится через стандартный PBKDF2-HMAC-SHA1, 600000 итераций, 256 бит; этот KDF выбран для совместимости с minSdk 21. Пароль при создании экспорта — минимум 12 символов. JSON файла: `type=dm.key`, `v=1`, `kdf=PBKDF2-HMAC-SHA1`, `iterations=600000`, `salt`, `iv`, `ct`. AAD: `dm.key|1|PBKDF2-HMAC-SHA1|600000|A256GCM`. В зашифрованной части `label`, `public` (DER X.509), `private` (DER PKCS#8). Перед импортом пара проверяется тестовой подписью, старые ключи не заменяются. Пароли не записываются в настройки, состояние Activity или журналы.

Передавайте пароль отдельно от файла. Без файла ключа после переустановки старые защищённые метки прочитать нельзя. Открытые метки от ключей не зависят.

## Чтение и сохранение

Сканирование камерой через ZXing, открытие PNG/JPEG через системный выбор файла, чтение JSON через системный выбор файла. Доступ к камере запрашивается только при запуске сканирования. Без камеры можно работать с файлами. Результат показывает всю карточку до записи в SQLite.

Совпадение определяется нормализованными организацией и инвентарным номером. Новая карточка открывается как черновик редактора. Существующая запись открывается в текущем виде либо заполняется данными QR после отдельного подтверждения; запись в БД выполняется только кнопкой сохранения. Если совпадение в корзине, предлагается восстановить его через реестр, а не создавать дубликат.

QR — снимок, автоматического обновления метки и синхронизации нет. Печать должна сохранять белое поле вокруг символа. Создаётся контрастный чёрно-белый PNG 1024×1024 с коррекцией ошибок M; лимит строки QR 2100 UTF-8 байт. Если данные не помещаются, они не обрезаются: доступно сохранение полного JSON. JSON ограничен 65536 байт, файл ключа 16384 байт, изображение 24 MiB и декодируется с уменьшением до 2048 px. Слишком длинные поля отклоняются до редактора: обычные 200 символов, причина/заметки 2000.
