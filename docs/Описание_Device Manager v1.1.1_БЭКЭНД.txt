Device Manager 1.1.1 — описание бэкенда

Архитектура
Общей серверной части нет. SQLite остаётся единственным хранилищем на каждом телефоне. Прямые Bluetooth-сканирование, RFCOMM-сервер и RFCOMM-клиент убраны из приложения. Android Sharesheet и системный документ-пикер обменивают файл через стандартные content URI. Из доступных на телефоне системных targets пользователь может выбрать Bluetooth, Quick Share или другое установленное средство.

В манифесте добавлен androidx.core.content.FileProvider с приватной областью `cache/device-transfers/` и grantUriPermissions. На отправке приложение выдаёт выбранному получателю временное право чтения конкретного `content://` файла через EXTRA_STREAM и ClipData. Открытого файлового пути и широкого доступа к хранилищу нет. Старые BT-права (SCAN, CONNECT, ADVERTISE и legacy Location) удалены. Приложение не запускает фоновые службы.

Файл и проверка
DeviceTransferCodec формирует UTF-8 JSON envelope `{ type: "dm.devices", v: 1, count, sha256, records }`. Массив records содержит portable snapshot карточек в совместимом с QR виде. Локальные SQLite ID, timestamps и команды удаления не передаются. Обязательные поля и статусы валидируются через DeviceQrCodec.

Пакет ограничен 8 MiB и 1–250 записями. Получатель читает `application/json` через Storage Access Framework OpenDocument с ограничением размера, проверяет версию, количество и SHA-256 массива записей, затем показывает предпросмотр. SHA-256 обнаруживает повреждение файла, но не является подписью отправителя.

Импорт
Перед записью приложение сравнивает нормализованные organization + inventory number со всеми локальными карточками, включая корзину. Получатель должен явно подтвердить предпросмотр. После этого DeviceRepository.importNew вставляет в одной SQLite-транзакции новые записи с новыми локальными ID и временными метками. INSERT OR IGNORE и уникальный индекс гарантируют, что существующая запись не перезапишется; совпадение учитывается в итоговом числе дубликатов. Отклонение или уход назад не меняет базу.

Совместимость и ограничения
- Android API 21+, target SDK 34, versionCode 5, versionName 1.1.1.
- Для отправки и приёма не запрашиваются Bluetooth-разрешения. Разрешения, сопряжение и шифрование канала зависят от выбранного Sharesheet-target и Android; приложение не утверждает, что каждый target использует одинаковую защиту.
- Для приёма нужен файл JSON, уже сохранённый или доступный через провайдера документов на устройстве.
- Максимум 250 записей / 8 MiB на файл.
- QR-протокол и ключи организации остаются отдельным способом обмена и не меняются.
