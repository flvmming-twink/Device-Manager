Device Manager v0.1.0 (1)
БЭКЭНД

Архитектура
Нативное Android-приложение на Kotlin. Под бэкендом этой версии понимается локальный слой данных и бизнес-правил; удалённый сервер не создавался.
Пакет установки: ru.misis.devicemanager. Отдельный package позволяет устанавливать Device Manager рядом с Contact Manager, не изменяя его базу.
Минимальная версия Android — 5.0 (API 21), compileSdk/targetSdk — 34, JDK 17, Gradle 8.6.
Основные слои:
- data/Device.kt — модель, статусы, нормализация, проверки и выборка.
- data/DeviceRepository.kt — операции SQLite.
- data/DeviceCsv.kt — экспорт.
- ui/DeviceViewModels.kt — состояние экрана и фоновые операции, переживающие пересоздание Activity.
- ui/DeviceListActivity.kt и DeviceEditorActivity.kt — взаимодействие с пользователем.
- core/ThemeManager.kt — перенесённая основа оформления.

Хранилище
Файл device_manager.db в приватном каталоге приложения. SQLite — единственный источник данных, без дублирующего зеркала SharedPreferences.
Таблица devices:
_id, name, inventory_number, inventory_key, serial_number, category, organization, organization_key, building, room, responsible, notes, status, write_off_reason, created_at, updated_at, deleted_at.
Идентификатор — SQLite AUTOINCREMENT. Время — Unix epoch в миллисекундах.
status: ACTIVE или WRITE_OFF; допустимые значения закреплены CHECK-ограничением SQLite.
Индекс по удалению, статусу и расположению. Уникальный индекс на паре organization_key + inventory_key.
Ключи нормализуются через Unicode NFKC, приведение к нижнему регистру Locale.ROOT и свёртку пробелов. Разный регистр кириллицы не позволяет обойти уникальность. Один номер допустим в разных организациях.

Операции и правила
- При первом запуске база пуста: демонстрационные устройства и старые контакты не добавляются.
- Сохранение проверяет обязательные поля и причину списания. Строки обрезаются по краям.
- Создание/изменение выполняется транзакционно. Редактирование сохраняет идентификатор и время создания, обновляет время изменения.
- Коллизия инвентарного номера не меняет существующую запись.
- Состояние WRITE_OFF является пометкой для учёта, а не юридическим актом или удалением.
- Мягкое удаление выставляет deleted_at. Восстановление очищает его и сохраняет остальные данные.
- Номер остаётся занят и в корзине, чтобы восстановление не создавало конфликтов. Окончательное удаление доступно только для записи в корзине и освобождает номер.
- Сохранение из устаревшего окна не восстанавливает удалённую запись.
- Версия схемы — 1. При последующих изменениях нужны явные миграции; автоматического удаления таблицы при обновлении нет.
- Операции базы выполняются на Dispatchers.IO. Поиск/фильтрация списка — на Dispatchers.Default. Состояние операций сохранения находится во ViewModel.
- Поиск выполняется по текущему реестру в памяти; это базовая версия для локального реестра, без обещания неограниченного объёма или многопользовательской работы.

Экспорт
CSV с UTF-8 BOM, разделителем «;», CRLF между строками и кавычками вокруг всех полей. Внутренние кавычки удваиваются, многострочные примечания сохраняются.
Значения с префиксами формул (=, +, -, @, табуляция/CR) защищаются апострофом перед передачей в табличный редактор.
Экспортируется снимок видимого списка, без корзины. Android Storage Access Framework предоставляет доступ только к выбранному пользователем файлу.
Разрешения на контакты, камеру, сеть и уведомления удалены. Старый механизм автообновления Contact Manager не запускается.

Проверки
DeviceRulesTest: обязательные поля, статусы, нормализация ключей, поиск, совместные фильтры, сортировка и CSV.
DeviceRepositoryTest: сохранность данных после повторного открытия SQLite, изменения карточки, уникальность, транзакционность, удаление, восстановление и устаревший редактор.
InventoryFlowTest: создание через редактор, поиск, списание с причиной, перемещение и сохранение черновика при пересоздании Activity.
Результаты: 20 тестов пройдено; lint — 0 ошибок, 59 предупреждений; assembleDebug — успешно. На эмуляторе Android 9 проверены создание, повторный запуск, списание, удаление и восстановление. Отчёты сохранены в versions/Device Manager v0.1.0/verification/.

Сохранение исходника
Неиспользуемые контактные классы, экраны, строки и старые workflow публикации перенесены в archive/contact-manager/legacy-android/. Исходные теги, пять ZIP версий и APK Contact Manager не изменялись.
Новый workflow build-apk.yml выполняет тесты, lint и сборку Device Manager; публикации релиза автоматически не выполняет.
